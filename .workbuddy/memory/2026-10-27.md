# 2026-10-27

## §18.14 · 探测历史语义化内容（输入 / 思考 / 输出）+ X-Req-Id 常驻展示

需求：检测任务执行历史时，把「用户发送的输入内容 / 模型思考内容 / 模型输出内容」
解析出来落库；并在每次请求上展示 x-req-id 方便定位问题。

### 落地内容

**新增 `internal/protocol/content.go`**（本增量核心）：
- `ExpandVars` —— 三个适配器此前各抄一份 `${var}` 展开实现，收敛到一处，
  保证「落库的输入内容」与「实际下发的请求体」逐字一致
- `BuildInput(cfg)` —— 把任务配置渲染成 `[system]\n…\n\n[user]\n…` 分块文本
- `TextAccumulator` —— 带上限（16 KiB）文本累加器，线程安全，
  **截断回退到合法 UTF-8 边界**（按字节切会切出半个汉字）
- `ContentCapture` —— `ProbeStream` 的附加出口
- `RequestError` —— 携带 `RequestID` / `RequestBody` / `ResponseBody` 的错误类型

**schema**：`probe_runs` 新增 5 列
`input_content` / `thinking_content` / `output_content` / `content_truncated` /
`response_error_body`（GORM AutoMigrate 自动加列，幂等）。

**三协议 reasoning 字段对照**（差异全部收敛在 adapter 内）：
- OpenAI 兼容：`delta.reasoning_content` / `delta.reasoning` / `delta.thinking`
- Anthropic：`content_block_delta` 且 `delta.thinking`（thinking_delta 帧）
- Gemini：`parts[].thought == true`

### 关键设计取舍（后续改动请勿推翻）

1. **thinking 必须在 adapter 当下按帧提取**，不能事后从 `response_head/tail` 反解
   —— 那是 HAR 风格首尾各 4 KiB，中间字节被丢弃，跨帧推理流必然断裂。
2. **推理 token 不计入 chunks / TTFT / ITL** —— 那三个指标衡量的是
   「面向用户的响应流」。为此 `protocol.Chunk` 新增 `Kind` 字段
   （零值 = ChunkContent，既有生产者与测试桩无需改动）。
3. **输入内容从 TaskConfig 还原**，而不是解析 request_body —— 三个协议拼装
   请求体的方式不同，解析要写三套；从配置还原还能保证变量已展开。

### 顺带修掉的两个既有缺陷

- **`probe_runs.request_id` 在失败路径上整个丢失**：401/403/5xx 时 adapter 在
  拿到响应前就返回 error，stream 从未创建，runner 拿不到 rid。现在这些路径
  返回 `RequestError`，runner 用 `errors.As` 取回 rid + 上游错误响应体
  （上游常把真正原因写在这里，如 "Incorrect API key provided"）。
- **`openai.consume()` 丢尾帧**：scanner goroutine 结束（`scanDone`）与
  `scanOut` 中残留的终止帧同时就绪时，Go 的 `select` **随机**挑一个 ——
  终止帧约一半概率被丢弃，表现为「答案的最后一段偶尔消失」。
  已在 `case <-scanDone:` 分支补 drain 循环。

### 验证方式

单测：`internal/protocol/content_test.go`、`internal/probe/store_content_test.go`，
以及三协议各自的 reasoning 捕获测试 + runner 端到端落库测试。

端到端：用 mock OpenAI 上游（返回 reasoning_content + content；`bad-key` 返 401）
+ 真实二进制跑 `@every 3s`，确认成功与 401 两条路径的落库内容均正确。

### 已知既有问题（与本增量无关，勿误判为回归）

`internal/scheduler` 3 个测试 + `internal/server` 1 个测试**在改动前就是失败的**
（已用 `git stash` 验证）。根因：这些测试构造 `TaskConfig` 时没设
`Enabled: true`，而 `scheduler.Add()` 有意跳过 disabled 任务
（"disabled 任务永不进入 cron" 是该函数的既定语义）。属测试自身疏漏。

### 环境注意事项

- 本机 `HTTP_PROXY` 会拦截 curl 到 127.0.0.1 的 POST，请求本地服务需加
  `--noproxy '*'`。
- zsh 下 `rm -f /tmp/x*` 在无匹配时会让整条 `&&` 链中断；同理未加引号的
  变量不会按空格分词（`for k in $LIST` 会退化成单个元素）。
- `go fmt ./internal/...` 会重排 30+ 个既有文件（本仓库并非 gofmt-clean），
  提交前只对自己改动的文件格式化。

## 增量二：忽略上游 TLS 证书校验（insecure_skip_verify）

### 背景

用户报错：`probe: openai: do: Post "https://20.20.100.94:18089/v1/chat/completions":
tls: failed to verify certificate: x509: certificate signed by unknown authority`。
内网模型服务使用自签名证书，要求「添加忽略证书校验配置」。

### 设计要点

**双开关、OR 语义**，两层：

| 层级 | 位置 | 含义 |
|---|---|---|
| 实例级 | `Config.InsecureSkipVerify`（yaml `insecure_skip_verify`） | 整个部署不校验证书 |
| 任务级 | `TaskConfig.InsecureSkipVerify`（gorm 列 `insecure_skip_verify`） | 单个任务放行 |

OR 语义：全局开启后**所有**任务都跳过校验，任务级可单独放行。刻意设计为
全局开关不可被任务级反向关闭 —— 全局开启是运维显式声明的「本部署不校验证书」。

**分层来源**：`defaults → yaml → AI_MONITOR_* env → CLI flag(FlagOverrides)`。
env 为 `AI_MONITOR_INSECURE_SKIP_VERIFY`；flag 为 `--insecure-skip-verify`。
`FlagOverrides.InsecureSkipVerify` 用 `*bool`，因为普通 bool 无法表达
「未提供」与「显式 false」的区别。

### 关键实现

- **`internal/protocol/httpclient.go`（新建）**
  - `InsecureHTTPClient()`：包级 `sync.Once` 缓存共享 client。
    **必须包级而非 adapter 级** —— adapter 每次 probe 都重建（`Lookup`
    构造新的），per-adapter transport 会导致每次探测泄漏一个连接池。
    基于 `http.DefaultTransport.Clone()` 保留代理/超时/HTTP2，只放开证书校验。
  - `ClientFor(base, globalInsecure, cfg)`：选择 client；base 为 nil 时回退
    `http.DefaultClient`。
- **三协议 adapter**（openai/anthropic/gemini）：`a.http.Do(req)` →
  `protocol.ClientFor(a.http, a.insecureDefault, cfg).Do(req)`。
- **`internal/config/store_sqlite.go`**：`fingerprintAll` 的 `fpRow` / SELECT /
  哈希三处都必须加 `insecure_skip_verify`，否则改该字段不触发配置热重载。
  （这是最容易漏的一步。）
- **`internal/server/admin_task_handlers.go`**：PATCH 用 `*bool` 区分「未提供
  （保留原值）」与「显式 false」。
- **`mergeTaskConfig` 里 `existing.Timeout.String()` → `existing.EffectiveTimeout().String()`**：
  修掉 PATCH 时 timeout 校验报 "0s" 的问题。

### 顺带修复的既有 Bug

- **`internal/server/http.go` 路由挂载**：admin 任务路由原先仅在配置了 auth 时
  挂载，导致无鉴权部署下 PATCH 返回 404。改为 `Auth == nil` 时也注册路由。
- **`redactTask` / `respondStoredTask` 改为方法**，以便读取全局开关并返回
  `insecure_skip_verify_global` 字段。

### 测试

  nil base / 任务级 / 全局级）+ 共享性。

- `internal/probe/tls_test.go`：runner 端到端三态（不开启失败 / 任务级开启成功 /

- `internal/server/admin_task_handlers_test.go`：PATCH 合并语义 + 全局 TLS 字段上报。
