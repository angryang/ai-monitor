# 2026-11-13 · 监控任务改为选择 AI 服务提供商

延续 11-12 的「服务商注册表 / 扁平 AI 请求」改造，把**监控任务**也改成
引用服务商，与 AI 请求同构。

## 模型变更

- `config.TaskConfig` 只保留任务自身字段 + `provider_id`；协议 / 地址 /
  密钥 / 模型 / 超时 / TLS / thinking / 协议块全部变成 `gorm:"-"` 的运行期
  字段，由 `provider.Binder.BindTask` 在**探测时**填入。
- `NotifyConfig` 改用显式列名 `notify_enabled` / `notify_channel` /
  `notify_wecom_webhook_enc`，消除与 `TaskConfig.Enabled` 抢 `enabled` 列的
  旧 bug（通知开关此前从未落库）。
- `tasks` 表**重建**（SQLite 不能给已有表加 NOT NULL 列）：`provider_id`
  NOT NULL + 任务自身列。
- 新增 `provider.Binder`（探测期绑定，改服务商下一个 tick 即生效）、
  `provider.MigrateLegacyTasks`（旧任务上游 → 服务商，密文直拷）。

## 关键实现坑

1. **迁移必须早于 GORM AutoMigrate**：AutoMigrate 会先尝试
   `ALTER TABLE ADD provider_id NOT NULL` 并直接失败。因此
   `main.go` 改为先 `config.OpenDB` 拿到句柄 → 建 provider / request store →
   跑迁移 → 再 `config.NewSqliteStoreFromDB(db, …)` 跑 AutoMigrate。
2. **新表结构必须由 GORM 生成**：手写 `CREATE TABLE tasks_new` 与模型在
   引号 / 默认值上有差异，AutoMigrate 随后会「修复」它并重建表，且重建时
   只拷贝部分列 → `NOT NULL constraint failed: tasks__temp.name`。
   正确做法：`db.Table("tasks_new").AutoMigrate(&config.TaskConfig{})`，
   迁移后重建 `idx_tasks_name` / `idx_tasks_provider_id`。
3. **旧 `enabled` 列语义**：legacy 表里 `Notify.Enabled` 与
   `TaskConfig.Enabled` 共用一列；实测（真实库行为：enabled=0 的任务没有
   产生过 probe_runs）该列存的是**任务开关**，迁移时映射为任务的
   `enabled`，通知开关统一初始化为 false。
4. **服务商复用判据按端点而非密文**：AES-GCM 带随机 nonce，同一明文两次
   加密的密文不同，按密文比对永远匹配不上；改为比对协议 + 地址 + 模型。

## 接口与前端

- `/admin/tasks` 载荷改为 `provider_id`；响应不再含 protocol / base_url /
  api_key / model / timeout / TLS / thinking，改为内嵌 `provider` 摘要。
- 未知 `provider_id` → 400 `unknown_provider`；删除仍被任务引用的服务商 →
  409 `provider_in_use`（`details.tasks` 列出任务名）。
- 前端：任务表单改服务商下拉（只读展示上游信息），列表「协议 / 模型」两列
  合并为「服务商」列，详情页上游信息改从内嵌服务商读取。

## 本地启动服务的两个坑

- `scripts/run-local.sh --bg` 用 nohup 起的进程，在本会话里会随启动它的
  shell 退出被回收：脚本自身报告 healthz 200，几秒后端口就没监听了，
  日志里只有 `seed_admin_exists` + 一次健康检查，没有 panic（不是崩溃）。
  需要持续运行时用受任务托管的前台方式：`./scripts/run-local.sh 2>&1 | tee /tmp/ai-monitor.log`。
- 机器上有 `HTTP_PROXY=http://127.0.0.1:55904`，直接 `curl localhost:9090`
  会走代理，服务没起来时返回的是代理的 502 `upstream connect failed`
  而不是 connection refused，容易误判。验证必须加 `curl --noproxy '*'`，
  python urllib 用 `ProxyHandler({})`。
- 改过前端后启动要加 `--rebuild`（或删除二进制），因为 SPA 是以
  `-tags=prod` `//go:embed` 编进 Go 二进制的；脚本的 stale 检测只看
  `cmd/` / `internal/` 下文件 mtime，不会因 `web/dist` 变化触发重编译。
- `.local-secrets` 已存在且 DB 非空，启动时**不要加 `--clean`**，复用主密钥
  才能解开存量 api_key。启动命令：`./scripts/run-local.sh --rebuild`。

## 服务商多模型 + 任务/请求各自选定模型

需求：一个 AI 服务商可配多个模型；AI 请求与监控任务只能选其中一个。
用户确认的方案：**模型名数组 + 引用方存名称**（不建独立表、不加外键）；
**保存不再强制连通性校验**，改为按模型单独点「测试」。

- 数据模型：`provider.Provider` 用 `Models []string` + `ModelsJSON`（列
  `models`，JSON 数组），`Model string` 保留为遗留 NOT NULL 镜像列
  （SQLite 不能原地删列，写入时镜像 `Models[0]`，新代码禁止读取）。
  `config.TaskConfig` 与 `request.Request` 各新增**持久化必填** `Model`。
  `Binder.BindTask` / `request.taskConfigFor` 改用使用方自己的 Model，
  不在候选列表里返回 `provider.ErrModel`。
- 迁移：`provider.MigrateMultiModels` 必须排在 AutoMigrate 之前；给
  ai_providers 加 `models`、给 tasks / ai_requests 加 `model` 并按
  provider_id 回填主模型，幂等。`MigrateLegacyTasks` 重建任务的 INSERT
  也显式带 `model`。`config.fingerprintAll` 的 hash 纳入 model。
- 接口：写载荷 `models: string[]`（兼容单值 `model`）；`force` 保留但无效；
  create/PATCH 不发上游请求、不返回 `check`、不设 LastVerified*。
  `CheckModel(ctx, p, model)` 一次测一个模型；`POST /admin/providers/check`
  用 payload 的 `model` 指定，`/{id}/check` 用可选 body 指定，缺省测主模型。
  移除仍被引用的模型 → 409 `model_in_use`（details 点名 requests/tasks）；
  写入引用不存在的模型 → 400 `unknown_model`。
- 前端：服务商表单改成可增删多模型行（每行单独「测试」），任务/请求表单
  加「服务商 → 模型」二级联动；所有只读展示改为各自选中的模型。
  中英文 i18n 同步。

### 本次踩坑

- `go test -race ./...` 里 `TestRunner_TTFT_It_Duration` 偶发
  `duration must be > 0`：stub adapter 同步返回，start/end 可能落在同一
  clock tick，Duration() 合法地为 0。断言改为「时间戳已填 + 间隔非负」。
- PATCH 只改 `provider_id` 而不带 `model` 会因旧模型不属于新服务商而返回
  400 `unknown_model`；前端联动会带上，API 调用方需同时改 model。
  测试与 e2e 脚本里的 re-point 都补了 model。
- e2e 脚本用 urllib 访问 127.0.0.1，要设 `NO_PROXY=127.0.0.1,localhost`，
  否则会走本机 HTTP_PROXY。
