# 2026-11-12

## 修复 `make build` 报错（全新检出无法构建）

### 症状
用户报 `make build` 报错。本机 `make build` 可正常执行，但根因是 **`internal/webui/dist/`
缺失时编译失败**——该目录在 `.gitignore` 中（构建产物），全新检出没有它。

报错（Go 编译器）：
```
internal/webui/embed.go:16:12: pattern dist: no matching files found
```

### 根因（三个叠加的缺陷）

1. **`//go:embed dist` 没有 build tag** —— `internal/webui/embed.go` 里是无条件 embed，
   于是 gitignored 的 `internal/webui/dist/` 成了**编译期硬依赖**。全新检出时
   `make build` / `go build ./...` / `go test ./...` 全部失败。
   代码注释里其实早就写好了 dev 回退路径（`static.go` 从 `web/dist` 读盘），
   但因为包根本编译不过，那条回退路径不可达。

2. **`make web-build` 的拷贝步骤从不创建目标目录** —— 原来是一行 Python one-liner：
   ```python
   shutil.copy2(src, dst)   # dst 目录不存在时抛 FileNotFoundError
   ```
   注意 Python 3.13 的报错把文件名报成**源路径**（`copyfile 'src' -> 'dst': 'src'`），
   很有迷惑性；实际缺的是**目标目录** `internal/webui/dist`。
   连带副作用：拷贝从不清理陈旧文件，dist 里会残留上一版的哈希产物。

3. **Dockerfile 在 `golang:1.25` 里跑 `make build`** —— 该镜像没有 Node.js，
   且 `.dockerignore` 缺失导致本地产物被塞进构建上下文。

### 改动
- `internal/webui/`：`embed.go` 拆成 `embed_prod.go`（`//go:build prod`，真 embed）
  与 `embed_dev.go`（`//go:build !prod`，空 FS → 走 `ErrNoAssets` → 读盘回退）。
  公开 API（`FS()` / `ErrNoAssets`）不变。
- `Makefile`：
  - `build` → 依赖 `internal/webui/dist/index.html`，缺失时自动 `make web-build`；
    编译加 `-tags=prod`。
  - 新增 `build-dev`：纯后端二进制，不内嵌 SPA，不需要 Node.js，全新检出即可编译。
  - `web-build` 拷贝步骤改用 `rm -rf` + `mkdir -p` + `cp -R`（去掉 python3 依赖，
    golang 基础镜像里没有 python3），顺带清掉陈旧哈希产物。
  - `anti-ai-grep`：字体检查改用 `grep -w`——原先裸子串 `Inter` 会误命中
    `setInterval`/`clearInterval`，导致守卫在正确代码上失败。
- `scripts/run-local.sh`：编译加 `-tags=prod`；dist 缺失时尝试 `make web-build`，
  失败或无 npm 则降级为 dev 二进制。
- `deploy/Dockerfile`：新增 `node:22-alpine` 阶段构建 SPA，再拷进 embed 目录。
- 新增 `.dockerignore`：排除 `web/node_modules`（74M）、`internal/webui/dist`、
  本地 DB/二进制/pcap/tar。
- `internal/scheduler/scheduler_test.go`：3 个用例的 fixture 漏了 `Enabled: true`。
  `Add()` 按设计跳过 disabled 任务（该语义有 `TestScheduler_Add_DisabledIsNoOp` 覆盖），
  于是这 3 个用例要么不 fire、要么不返回 cron 解析错误 → `make test` 长期红。

### 验证
- 全新检出模拟（`mv internal/webui/dist` 隐藏）：
  `go build ./...` / `go vet ./...` / `make build-dev` / `make build`（自动补齐 SPA）全部 exit 0。
- 端到端：在**没有 web/dist** 的临时目录跑产出的二进制，`/` 与哈希资源均 200，
  证明资源确实来自二进制内嵌。
- `make test`（-race）/ `make lint` / `make anti-ai-grep` 全绿。

### 遗留（未改，已向用户报告）
- `internal/scheduler/scheduler_test.go` 中 `TestScheduler_AddRemove`、
  `TestScheduler_MaxConcurrent`、`TestScheduler_Reload` 三个用例同样是**空跑**
  （fixture 无 `Enabled: true`，任务从未注册，断言无意义）。
  其中 `TestScheduler_MaxConcurrent` 还有潜在死锁：handler 阻塞在 `<-gate`，
  而 `s.Stop()` 会等 in-flight 结束，`close(gate)` 却排在 `Stop()` 之后——
  一旦把任务启用就会 hang，故未贸然改动。

### 环境备忘
- macOS 的 BSD grep **不支持 BRE 交替 `\|`**，必须用 `-E`；本轮多次 grep 因此漏匹配。
- Python 3.13 `shutil.copy2` 目标目录缺失时，报错里的 filename 是**源路径**。
