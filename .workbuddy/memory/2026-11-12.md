## 修复 `make build` 报错（全新检出无法构建）

### 症状
用户报 `make build` 报错。本机 `make build` 可正常执行，但根因是 **`internal/webui/dist/`
缺失时编译失败**——该目录在 `.gitignore` 中（构建产物），全新检出没有它。

报错（Go 编译器）：
```
internal/webui/embed.go:16:12: pattern dist: no matching files found
```

### 根因（三个叠加的缺陷）

1. **`//go:embed dist` 没有 build tag** —— `internal/webui/embed.go` 里是无条件 embed，
   于是 gitignored 的 `internal/webui/dist/` 成了**编译期硬依赖**。全新检出时
   `make build` / `go build ./...` / `go test ./...` 全部失败。
   代码注释里其实早就写好了 dev 回退路径（`static.go` 从 `web/dist` 读盘），
   但因为包根本编译不过，那条回退路径不可达。

2. **`make web-build` 的拷贝步骤从不创建目标目录** —— 原来是一行 Python one-liner：
   ```python
   shutil.copy2(src, dst)   # dst 目录不存在时抛 FileNotFoundError
   ```
   注意 Python 3.13 的报错把文件名报成**源路径**（`copyfile 'src' -> 'dst': 'src'`），
   很有迷惑性；实际缺的是**目标目录** `internal/webui/dist`。
   连带副作用：拷贝从不清理陈旧文件，dist 里会残留上一版的哈希产物。

3. **Dockerfile 在 `golang:1.25` 里跑 `make build`** —— 该镜像没有 Node.js，
   且 `.dockerignore` 缺失导致本地产物被塞进构建上下文。

### 改动
- `internal/webui/`：`embed.go` 拆成 `embed_prod.go`（`//go:build prod`，真 embed）
  与 `embed_dev.go`（`//go:build !prod`，空 FS → 走 `ErrNoAssets` → 读盘回退）。
  公开 API（`FS()` / `ErrNoAssets`）不变。
- `Makefile`：
  - `build` → 依赖 `internal/webui/dist/index.html`，缺失时自动 `make web-build`；
    编译加 `-tags=prod`。
  - 新增 `build-dev`：纯后端二进制，不内嵌 SPA，不需要 Node.js，全新检出即可编译。
  - `web-build` 拷贝步骤改用 `rm -rf` + `mkdir -p` + `cp -R`（去掉 python3 依赖，
    golang 基础镜像里没有 python3），顺带清掉陈旧哈希产物。
  - `anti-ai-grep`：字体检查改用 `grep -w`——原先裸子串 `Inter` 会误命中
    `setInterval`/`clearInterval`，导致守卫在正确代码上失败。
- `scripts/run-local.sh`：编译加 `-tags=prod`；dist 缺失时尝试 `make web-build`，
  失败或无 npm 则降级为 dev 二进制。
- `deploy/Dockerfile`：新增 `node:22-alpine` 阶段构建 SPA，再拷进 embed 目录。
- 新增 `.dockerignore`：排除 `web/node_modules`（74M）、`internal/webui/dist`、
  本地 DB/二进制/pcap/tar。
- `internal/scheduler/scheduler_test.go`：3 个用例的 fixture 漏了 `Enabled: true`。
  `Add()` 按设计跳过 disabled 任务（该语义有 `TestScheduler_Add_DisabledIsNoOp` 覆盖），
  于是这 3 个用例要么不 fire、要么不返回 cron 解析错误 → `make test` 长期红。

## 新功能：AI 请求管理（一次性批量执行 AI 请求）

### 需求与选型
用户要「参考监控任务」新增 AI 请求管理：预定义一组 AI 请求，对指定服务商一次性发出；
可单选一条执行，也可多选多条一起执行。两个决策经用户确认：

1. **新增「请求组」一等实体**（不复用监控任务）：Group 绑定一个服务商
   （protocol / base_url / 加密 api_key / model / timeout / thinking 开关），
   Item 是组内一条预定义请求（system/user prompt + prompt_vars + 可选 thinking 覆盖）。
   执行整组 = 把组内全部请求一次性发给该组的服务商。
2. **手动执行不计入监控统计与告警**：照常落 `probe_runs` 历史，但不写 Prometheus
   指标、不写成功率滑窗、不触发企微告警。否则手动测一次超时会污染连续失败计数并误报警。

### 架构要点（后续维护必读）
- **执行必须异步**：`internal/server/http.go` 的 `WriteTimeout` 默认 **5s**，
  而 AI 请求默认 30s+。run 端点返回 `202 + batch_id`，前端轮询
  `GET /admin/request-batches/{id}`。批次状态在内存（重启丢失），
  持久记录是 `probe_runs` 行。
- `probe.Runner` 拆成 `Run`（调度样本）/ `RunManual`（手动）共用 `run(ctx, t, opts)`；
  `RunOptions.Manual` 门控所有指标 / 滑窗 / 告警调用，探测机制与历史写入不变。
  `Result` 与 `ProbeRun` 新增 `source` / `batch_id` / `group_id` / `item_id`；
  手动任务的合成 task_id 是 `req-<item_id>`，因此不会串进任何监控任务的历史。
- `internal/request` 包：`model.go`（Group/Item + Store 接口 + 错误哨兵）、
  `store_sqlite.go`（复用 config store 的 *gorm.DB + 同一把 AES cipher）、
  `service.go`（合成 TaskConfig → RunManual、批次注册表、并发上限、独立超时）。
  **合成 TaskConfig 只能带与 protocol 匹配的那个协议块**，否则
  `ValidateProtocolSegments()` 会拒绝（Anthropic 默认 MaxTokens=1024 会与 OpenAI 互斥）。
- `run` 端点都走 admin 角色门控；viewer 只能浏览。
- 前端：`views/RequestGroupsView.vue` + `components/requests/*` +
  `api/requests.ts` + `stores/requests.ts`；路由 `/requests`，侧栏 + 面包屑 + 中英 i18n。

### 踩过的坑（都修了，别再踩）
1. **数据竞争**：`start()` 原先返回「活的」`*Batch` 指针，`writeJSON` 序列化时后台协程
   正在改 `State/EndedAt/Results`。修法：服务对外一律返回快照；`snapshotLocked`
   里复制空切片必须用 `append([]T{}, ...)` 而**不是** `append([]T(nil), ...)`——
   后者对空切片返回 nil，JSON 就变成 `null`，前端 `.length` 直接崩。
   锁的获取要收进 `snapshot()` 方法内部，不能靠调用方自觉。
2. **局部 PATCH 被 400**：`groupFromPayload` 原本无条件校验 name/protocol/base_url/model，
   导致 `{"thinking_enabled":true}` 这种 PATCH 被拒，而 patchGroup 的合并分支成了死代码。
   修法：fromPayload 只解析+校验「出现过的」字段，必填校验改为 `validateGroup/validateItem`
   作用于**合并后**的结果（create 时作用于 payload）。`description` / `system_prompt`
   改成 `*string`，区分「未提及」与「显式清空」。
3. **协议块 JSON 契约**：`config.OpenAIConfig` 等只有 GORM/yaml tag，**没有 JSON tag**，
   直接复用到 DTO 会暴露 `StreamPath`/`ExtraHeadersJSON` 这类 Go 字段名。
   必须用显式 wire DTO（`openAIBlockPayload` 等）与 `toConfig()` / `*View()` 双向映射。
4. `order` 是 SQL 保留字 → 列名改 `sort_order`（Go 字段仍叫 Order，json 仍叫 order）。
5. GORM `Updates(map[string]any)` 必须先 `.Model(&T{})`，否则报
   "Table not set"。
6. **仓库本身不是 gofmt-clean**（早于 Go 1.19 注释重排）。只对自己新建的文件跑
   `gofmt -w`，**不要全量格式化**，否则会产生大片无关 diff。
7. 假上游 SSE 不能设 `Content-Length: 0`——客户端会认为响应体为空立即 EOF，
   表现为「输出为空、耗时 0、上游 BrokenPipe」。用 `Connection: close` 界定流式响应体。

## 追加：AI 请求管理支持「执行时自定义请求内容」

需求：预定义请求内容不再「保存即固定」，执行前要能自己写 user_prompt。

方案：**一次性覆盖（one-shot override）**，不新增实体、不落库、不改协议适配器。
- `internal/request/override.go`：`ContentOverride{SystemPrompt, UserPrompt *string; PromptVars map[string]string}`。
  指针区分「未提及」与「显式清空」；`PromptVars` 用 nil vs `{}` 同理。
  `apply()` 只改 Item 的**值拷贝**，map 也 clone —— Store 若返回缓存指针，
  否则一次临时改写会泄漏到下一次执行。
- `RunOptions.Overrides`（按 item_id），`Service.start` 在组装 `runTarget` 前应用。
  空白 user_prompt 在注册批次**之前**返回 `ErrInvalidConfig`，整批不发。
- 两个 run 端点共用 `runPayload`；新增 `readOptionalJSON` 容忍空 body（旧客户端调
  `/admin/request-groups/{id}/run` 不带 body），`DisallowUnknownFields` 仍生效。
- 前端 `RunContentModal.vue`：执行前弹窗按条目预填已保存内容，可逐条改
  user/system prompt 与 `${变量}`，支持「统一内容应用到全部」「恢复预定义」
  「按预定义执行」；只把**真正改过的字段**作为 overrides 发送。
- i18n 新增 `req.customize.*`（中英），README 补 payload 示例与语义。

约束不变：手动执行不计入 Prometheus / 成功率 / 企微告警；覆盖只影响本次批次，
`probe_runs.input_content` 记录的是实际发出去的内容（变量已展开）。

验证：`go test ./... -race -count=1`（14 包全绿）、`make lint`、`make anti-ai-grep`、
`npm run build`、`make web-build && make build`、E2E 11 组全 PASS。新增断言：
自定义内容经变量展开后确实被假上游 echo、预定义条目未被改写、下一次执行回落、

## AI 服务提供商管理（保存前强制连通性校验）

需求：可定义 AI 服务提供商，对其增删改查；**保存之前必须确认与上游连通**。

### 新增包 `internal/provider`
- `model.go`：`Provider`（GORM，表 `ai_providers`）+ `Store` 接口 + 哨兵错误。
  字段与 `config.TaskConfig` 对齐：protocol / base_url / api_key_enc / model /
  timeout_ms / insecure_skip_verify / thinking_enabled + 三个协议块；
  外加 `last_verified_at|ok|message` 记录最近一次校验结论。
- `store_sqlite.go`：与 task store **共享同一个 `*gorm.DB` 句柄**（同一 SQLite
  文件 / WAL / busy_timeout）；api_key 用同一把 master key 密封。
  **解密失败时保留密文**（只记 `secret_error`）——否则一次无关改名会把密钥抹掉。
- `connectivity.go`：`Checker.Check()` 复用 `protocol.ChatProtocolAdapter.Probe()`
  发**该服务商自己的请求**，读到响应头即判定可达，随后 `stream.Close()` 掐断生成。
  分类：`unauthorized`(401/403) / `invalid_request`(其余 4xx) / `upstream_unavailable`(5xx)
  / `timeout` / `network_error`(没拿到响应) / `config_error`(没发请求)。

### 关键决策
- **复用 adapter 而不是另写最小请求**：只有下发同一个请求，"服务商连得上"才等于
  "指向它的监控任务能跑"。
- **校验独立于监控信号**：不写 probe_runs、不进成功率窗口、不告警。
- **默认拒绝落库**，失败返回 422；`"force": true` 是显式豁免（结论仍返回，
  行标记为未通过校验）。
- **HTTP 写超时跟着校验超时抬**：新增 `server.Options.WriteTimeout`，
  main.go 设成 `cfg.ProviderCheckTimeout + 5s`，否则 10s 的校验会被 5s 掐断。
- **超时可配**：`provider_check_timeout`（默认 10s）/ `AI_MONITOR_PROVIDER_CHECK_TIMEOUT`。

### 协议包改动
`protocol.RequestError` 新增 `StatusCode int`，`NewRequestError` 多一个参数
（0 = 没拿到响应）。三个适配器 + 2 处测试同步更新。原因：不靠解析错误消息里的
`"status %d"` 来拿状态码。

### 接口（`/admin/providers`，读写权限同 request-groups）
`GET /` `GET /{id}` `POST /` `PATCH /{id}` `DELETE /{id}`
`POST /check`（只校验不落库）`POST /{id}/check`（用已存密钥复验）。
校验失败 → 422 + `error.code = provider_unreachable`，`error.details` 里带完整
`CheckResult`（`APIError` 新增可选 `Details` 字段；前端 `ApiError` 同步加 `details`）。

### 前端
`api/providers.ts`、`stores/providers.ts`、`components/providers/ProviderFormModal.vue`
（表单 + 「测试连通性」+ 结论面板 + 失败时「仍然保存」）、`views/ProvidersView.vue`、
路由 `/providers`、侧栏「AI 服务商」、中英 i18n `provider.*`。

### 模型与链路
- 旧模型 `request_groups`（内含上游坐标）+ `request_items`（挂在组下）彻底废弃；
